# native_sqlite_android

Android implementation of the `native_sqlite` plugin. Uses a native Kotlin plugin class (`NativeSqlitePlugin`) backed by Android's bundled SQLite.

Database names are restricted to ASCII letters, digits, underscores, and
hyphens. Files use the application's database directory by default; an
absolute `DatabaseConfig.directory` may be supplied for a location the app is
allowed to access. The minimum SQL feature baseline is SQLite 3.18 (API 26).

This package is automatically selected when your Flutter app runs on Android — you do not add it to your `pubspec.yaml` directly.

---

## Features

- Full CRUD, transactions, and raw SQL via the platform channel
- WAL journal mode requested by default; database-specific worker queues
  serialize Flutter and native access
- Kotlin schema helpers generated by `native_sqlite_generator` for native-side database access

---

## Native code generation

Running `dart run native_sqlite_generator` produces Kotlin files in the path configured by `native_sqlite_config.yaml`:

```
UserSchema.kt       ← column-name constants, CREATE TABLE and index SQL
UserHelper.kt       ← typed `User` data class and CRUD/query helper
UserStatus.kt       ← one file per Dart enum used by a model
DatabaseManager.kt  ← opens and migrates the database exactly like DatabaseManager.dart
```

Call `DatabaseManager.init(context)` before using the helpers from native code
(WorkManager, services, widgets). If Flutter already opened the database, the
open connection is reused. Native and Dart owners are reference counted, so
each manager can close its reference without invalidating the other. Reopening
a name with different version, schema, migration, WAL, or foreign-key settings
throws instead of silently replacing the live connection.

Generated native helpers are synchronous. Call them from a worker thread
(for example, WorkManager's worker); debug builds reject main-thread access.
Flutter method-channel calls are automatically pinned to one database-specific
worker thread.

Native callers can perform parameterized, interactive transactions on that
same worker thread:

```kotlin
NativeSqliteManager.Instance.transaction("app") { txn ->
    txn.execute("INSERT INTO events (value) VALUES (?)", listOf("started"))
    txn.query("SELECT * FROM events")
}
```

## Verified toolchain

CI builds with Flutter 3.47.5, Android Gradle Plugin 9, Java 17, and Android
API 26 through 36. The final supported lower bounds are intentionally not
promised until the release toolchain decision is recorded.

## Configuration (`native_sqlite_config.yaml`)

```yaml
native_sqlite:
  android:
    enabled: true
    output_path: 'android/app/src/main/kotlin/com/example/myapp/generated'
    package: 'com.example.myapp.generated'
    generate_helpers: true
```
